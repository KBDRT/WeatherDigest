# Консольная утилита «Погодный дайджест»
Стек: Javascript, Node.js

Консольная утилита получения прогноза погоды из открытого API Open-Meteo. <br>
По заданным пользователем параметрам (города, количество дней) утилита обращается к внешнему API, обрабатывает ответ и выводит пользователю.<br>
При любых ошибках: проблема с API, неправильные параметры - пользователь получает соответствующее сообщение с ошибкой.<br>
Корректные полученные данные сохраняются в виде JSON-файлов, и используются как кэш для последующих запусков утилиты.<br>

## Требования к окружению
- **Node.js** версия 20 или выше - запуск утилиты;
- **npm**: - установка дополнительных библиотек из зависимостей;
- **Доступ в интернет** - обращение к API;

## Инструкция по установке
1. Клонировать репозиторий
```
git clone https://github.com/KBDRT/WeatherDigest
```
2. Перейти в корневую папку утилиты
3. Установить библиотеки из зависимостей
```
npm i
```
4. Создать файл с переменными окружения (.env). [Пример файла (.env.example)](/.env.example)
5. Запустить утилиту
```
node src/index.js --city "Москва" --days 3 --nocache
```

## Переменные окружения
Утилита использует данные из переменных окружения (Файл .env). <br>
[Пример файла (.env.example)](/.env.example) 
| Переменная окружения | Описание | Пример значения |
|:-----------|:-----------|:-----------|
PARAMETER_CITY_NAME |Название параметра 'города' для чтения при запуске утилиты| --city
PARAMETER_DAYS_NAME|Название параметра 'кол-во дней' для чтения при запуске утилиты| --days
PARAMETER_DAYS_DEFAULT_VALUE|Значение параметра 'дней' по умолчанию| 3
PARAMETER_DAYS_MIN_VALUE|Минимальное значение параметра 'дней'| 1
PARAMETER_DAYS_MAX_VALUE|Максимальное значение параметра 'дней'| 7
PARAMETER_NOCACHE_NAME|Название параметра 'использование кэширования' для чтения при запуске утилиты| --nocache
BASE_URL_GEOCODING|Базовый URL для получения геокодинга| https://geocoding-api.open-meteo.com/v1/search
BASE_URL_WEATHER|Базовый URL для получения погоды| https://api.open-meteo.com/v1/forecast
API_TIMEOUT|Ограничения времени запроса к API (Таймаут)| 5000
REPORTS_FOLDER|Папка для сохранения JSON-отчета| reports
CITY|Значение параметра города при запуске утилиты с чтением параметров из переменных окружения (`npm run withEnv`)| Казань
DAYS|Значение параметра дней при запуске утилиты с чтением параметров из переменных окружения (`npm run withEnv`)| 5
NOCACHE|Значение параметра города при запуске утилиты с чтением параметров из переменных окружения (`npm run withEnv`)| true

## Команды запуска
Основной запуск утилиты:
```
node src/index.js --city "Москва" --days 3 --nocache
```
| Параметр | Описание | Обязательный
|:-----------|:-----------|:-----------
--city|Город (или список) городов для получения погоды. Список городов разделяется `,`|Да
--days|Количество дней прогноза|Нет, по умолчанию берется значение из переменной окружения PARAMETER_DAYS_DEFAULT_VALUE
--nocache|Не учитывать сохраненный кэш (JSON-файл), всегда обращаться к API|Нет

Дополнительные команды запуска описаны в [package.json](/package.json) <br>
| Команда | Описание |
|:-----------|:-----------|
`npm start`|Аналог основного запуска: перед параметрами запуска необходимо добавить дополнительно `--`. (`npm start -- --city "Москва"`)
`npm run withEnv`|Параметры запуска: days, city, nocache будут считываться из переменных окружения
`npm run example:success`|Запуск с параметрами `--city Москва --days 5 --nocache`
`npm run example:not-found`|Запуск с параметрами `--city НетТакогоГорода --days 5`
`npm run example:bad-params`|Запуск с параметрами `--days 5 `
`npm run prettier:check`|Запуск проверки Prettier
`npm run eslint:check`|Запуск проверки ESlint
`npm run test:geocoding`|Запуск тестов для Geocoding функций
`npm run test:weather`|Запуск тестов для Weather функций

## Описание обрабатываемых ошибок
1. Во время работы утилиты происходит чтение параметров запуска и использование переменных окружения, при нахождении ошибок утилита завершается и пользователю выводится соответствующее сообщение.

- Чтение параметров запуска с обработкой ошибок реализовано в [parameter-parser.js](/src/utils/parameter-parser.js).
- Файл с переменными окружения обрабатывается в [validator.js](/src/config/validator.js).

Код завершения процесса при этих ошибках **0**.
<br><br>
Обрабатываемые ошибки:

| Ошибка | Пример запуска | Пример результата в терминале
|:-----------|:-----------|:-----------
Отсутствует параметр --city|`node src/index.js --days 5 `|`Ошибка! Для параметра --city не указано значение!`
Значение параметра --days выходит из диапазона|`node src/index.js --days 11`|`Ошибка! Параметр --days должен быть целым числом в диапазоне от 1 до 7 включительно.`
Не найдено значение в переменных окружения |Удалить из файла (.env) параметр PARAMETER_CITY_NAME и запустить |`Ошибка файла с переменными окружения (.env)! Параметр: PARAMETER_CITY_NAME не найден!`
Значение переменной окружения не число |Поменять на строку параметр PARAMETER_CITY_NAME из файла (.env) и запустить |`Ошибка файла с переменными окружения (.env)! Параметр: PARAMETER_DAYS_MIN_VALUE не является числом!`

<br>
2. При работе с API и результатами запроса обрабатываются свои ошибки.
<br><br>

Список всех ошибок представлен в файле [parameter-parser.js](/src/utils/parameter-parser.js). 
<br>
При срабатывании одной из ошибок в консоль выводится `Название города:Ошибка`. 
<br>
В этом случаи код завершения процесса **1**, т.к. утилита выполнилась успешно, проблема с внешними сервисами/запрашиваемыми данными.
<br><br>
Основные обрабатываемые ошибки:

| Ошибка | Пример результата в терминале
|:-----------|:-----------
Таймаут|`Москва:  Превышение таймаута.`
Город не найден|`Набережные Челны1: Город не найден!`
В запрос к API попадают невалидные данные (Ошибка 400)|`Москва:  Ошибка клиента. Статус: 400. Текст: Bad Request. Причина: Forecast days is invalid. Allowed range 0 to 16. Given 16.`
Проблема с доступом к API (Ошибка 500)|`Москва:  Ошибка сервера. Статус: 500.`
API вернуло некорректный JSON-ответ|`Москва:  Неверный JSON файл в ответе.`

## Описание структуры проекта

Функции утилиты распределены по [папками](/src) в соответствии с их областями отвественности.

| Модуль | Описание
|:-----------|:-----------
[/api](/src/api)|Функции с выполнением запроса к API и обработкой результата
[/config](/src/config)|Чтение файла с переменными окружения и его валидация
[/errors](/src/errors)|Классы, наследующие базовый класс исключения Error
[/format](/src/format)|Класс printer.js для вывода пользователю полученной информации о погоде
[/models](/src/models)|Классы с моделями данных (Город, Погода)
[/services](/src/services)|Основной класс с логикой утилиты, занимается обработкой одного города и вызова необходимых функций.
[/storage](/src/storage)|Запись и чтение кэша в виде JSON-файлов
[/utils](/src/utils)|Дополнительные утилиты: генерация сообщения об ошибке, парсер параметров запуска и другие.

## Дополнительное задание:
### Docker

Созданы [dockerfile](Dockerfile) и [.dockerignore](.dockerignore) для сборки образа. 
<br><br>
Для чтения параметров из переменных окружения создан отдельный запуск утилиты:

```
npm run withEnv
```
В файле для чтения параметров запуска [parameters-parser.js](/src/utils/parameters.js) реализовано условие для сравнения запуска и использования переменных окружения:
```
if (process.env.npm_lifecycle_event == 'withEnv')
```
<br>
Для запуска в Docker, находясь в корневой папке с утилитой:
<br><br>

Собрать образ:
```
docker build -t digest
```

Запустить контейнер с образом, передав в параметрах файл с переменными окружения:
```
docker run -d --env-file .env digest
```
<br>

Параметры запуска считываются из [.env](.env.example):
```
CITY=Казань
DAYS=5
NOCACHE=true
```

При необходимости можно передать переменные окружения с параметрами во время запуска контейнера:
```
docker run -d --env-file .env -e CITY=Москва  digest 
```
